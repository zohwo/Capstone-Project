# 모듈 1: 블랙파우더 성분 데이터 전처리 파이프라인 설계

- 작성일: 2026-09-28
- 대상 모듈: 모듈 1 (데이터 가공)
- 원본 데이터: `data/raw/영풍그룹_금속회수율최적화_RawMaterialData_학생배포용.xlsx`
  - 시트 `원료분석_원본데이터`: 424행 16컬럼 (배치 단위 원료 조성/공정조건/회수율 실측값)
  - 시트 `데이터사전`: 16개 컬럼에 대한 설명·단위·정상 범위 정의 (검증 기준으로 사용)

## 1. 배경 및 목표

랩실에서 배치(BP-2025-XXXX)별로 원료(블랙파우더) 성분을 분석한 원본 데이터는 다음 문제를 가진다:

- `분석일자` 컬럼에 6종 이상의 날짜 표기 형식이 혼재 (`2025-01-02`, `2025/01/02`, `03.01.2025`, `20250103`, `Jan 03, 2025`, `01/03/25`)하고 22건 결측
- `원료등급` 컬럼에 표기 불일치 (`A`, `A급`, `a`, `" A "`, `B급`, `b` 등 12개 변형이 실질 3개 등급 A/B/C를 가리킴)
- 조성/불순물 컬럼(Ni/Co/Li/Mn_함량, Cu/Fe/Al_불순물) 8종에 각 25~35건(6~9%)의 랜덤 결측
- 공정조건 컬럼(침출온도_C, 침출시간_hr)에 결측 및 물리적으로 불가능한 값(온도 -5.0℃) 포함
- 명백한 입력/센서 오류로 보이는 이상치: `Ni_함량_pct=999.0`(정상범위 8~30), `황산투입량_L=15000`(정상범위 400~1500)
- `배치ID` 420 unique / 424행 → 4건 중복

목표: 이 원본 데이터를 머신러닝(니켈/코발트 회수율 예측) 입력으로 쓸 수 있도록, **재실행 가능하고 형식이 달라도 수동 개입 없이 동일 품질로 정제되는** 파이프라인을 구축하고, 회수율에 영향을 미치는 파생변수를 도메인 지식에 근거해 추가한 뒤, 정제 결과를 정량적으로 검증한다.

## 2. 산출물 형태

두 가지를 모두 만든다:

1. **재사용 가능한 파이프라인 모듈** (`src/` 이하 파이썬 코드) — 새로운 원본 파일이 들어와도 동일 로직으로 정제·저장
2. **분석 노트북** (`notebooks/01_eda_and_validation.ipynb`) — 파이프라인 함수를 호출해 EDA, 전/후 비교 시각화, ablation test 결과, 심층 인터뷰 3문항에 대한 답변을 정리

## 3. 파이프라인 아키텍처

```
load_raw()  →  clean_schema()  →  handle_missing()  →  engineer_features()  →  validate()  →  save
```

모듈 구성 (`src/` 아래):

| 파일 | 책임 |
|---|---|
| `preprocessing.py` | `load_raw(path)`: xlsx/csv 확장자 분기 로딩. `clean_schema(df)`: 날짜 파싱·표준화, 범주형(`원료등급`) 정규화, 중복 배치ID 탐지·플래그 |
| `imputation.py` | `flag_outliers(df)`: 정상범위(데이터사전 기준) 밖 값을 NaN으로 치환하며 플래그 컬럼 생성. `impute_missing(df)`: §4 규칙에 따른 대치 |
| `features.py` | `engineer_features(df)`: §5 파생변수 5종 생성 |
| `validation.py` | `validate(df)`: 정상범위 재검증, 분포/상관 시각화 저장, 파생변수 ablation test 실행 |
| `pipeline.py` | 위 함수들을 순서대로 호출하는 엔트리포인트. `python -m src.pipeline`로 실행하면 `data/processed/cleaned_features.csv` 생성 |

각 함수는 DataFrame을 입력받아 DataFrame을 반환하는 순수 함수로 작성하여, 노트북과 파이프라인 스크립트 양쪽에서 동일하게 재사용한다. 이 구조 덕분에 "매번 형식이 다른 원본 데이터가 들어와도 동일 품질로 정제"된다는 요구사항을 만족한다: 원본 파일이 바뀌어도 `load_raw` → `pipeline.run()` 호출 한 번으로 동일한 정제 규칙이 적용된다.

## 4. 결측치·이상치 처리 규칙

| 컬럼군 | 처리 | 근거 |
|---|---|---|
| `Ni_함량_pct`(999.0), `침출온도_C`(<0), `황산투입량_L`(>1500 대비 10배 이상) | 데이터사전 정상범위를 크게 벗어나면 NaN으로 치환 (이상치→결측 변환) | 물리적으로 불가능한 값은 센서/입력 오류로 판단. 예: 니켈 함량 wt%가 30%를 초과하거나 침출온도가 음수인 것은 습식제련 공정상 불가능 |
| 조성 8종 (Ni/Co/Li/Mn_함량, Cu/Fe/Al_불순물) | `원료등급`(A/B/C) 그룹별 중앙값 대치 | 원료등급 정의 자체가 "고니켈·저불순물(A)~저니켈·고불순물(C)"이므로 등급별 조성 분포가 다름. 전체 중앙값 대치는 등급 간 실제 차이를 희석시키는 편향을 유발. 평균이 아닌 중앙값을 쓰는 이유는 잔존 이상치에 대한 강건성 확보 |
| `침출온도_C`, `침출시간_hr` | 중앙값 대치 (시계열 보간 미적용) | 배치식 공정은 배치마다 독립적으로 운전조건이 설정되어, 날짜순으로 인접한 배치라고 조건이 비슷하다는 물리적 근거가 없음. 보간 시 허구의 연속성을 만들 위험이 있어 배제 |
| `황산투입량_L` (이상치 1건) | `원료투입량_kg`을 예측변수로 한 선형회귀 대치 | 황산 투입량은 광석 질량에 비례하는 화학양론적 관계(산-광석비)를 가짐. 정상 데이터로 학습한 회귀식으로 결측/이상치를 대치하는 것이 중앙값보다 물리적으로 타당 |
| `분석일자` (22건 결측) | 배치ID 순번 기준 정렬 후 시간 보간(`interpolate`) | 배치ID가 순차 발번되어 생산·분석 순서를 근사하므로, 이 컬럼에 한해 순서 기반 보간이 타당한 유일한 케이스 |
| `원료등급` 표기 불일치 (`A급`/`a`/`" A "` 등) | 공백 제거 + 대문자화 + `급` 접미사 제거 → `A/B/C` 표준화 | 결측치 처리가 아닌 범주 정규화. 그룹별 대치가 제대로 동작하려면 선행 필수 |
| `배치ID` 중복 4건 | 삭제하지 않고 `is_duplicate_batch` 플래그 컬럼 추가 | 원본 데이터 감사(audit) 목적상 임의 삭제보다 플래그 후 판단 위임이 안전 |

## 5. 컬럼 역할 정의 (모델 피처 vs 유지용 메타데이터)

- **모델 피처에서 제외, 데이터셋엔 유지**: `배치ID`(순수 식별자, 학습 시 가짜 상관관계 유발 위험), 원본 `분석일자`(공정에 인과적 영향을 주는 물리량이 아님. 단, 계절성 확인을 위해 파생된 `분석월`은 상관관계 체크 후 채택 여부 결정)
- **유지 + 모델 피처 잠정 포함**: `원료등급`. 전처리 단계의 그룹별 대치 키로 필수이며, 조성 변수만으로 설명되지 않는 비선형 조합 정보를 담고 있을 가능성이 있어 잠정 포함. 모델 피처로서의 최종 채택 여부는 §6.2 ablation test 결과에 따라 확정
- **`데이터사전` 시트**: 메인 데이터프레임으로 로드하지 않음. 정상범위 검증 규칙의 소스로만 코드 내 상수/설정으로 사용

## 6. 특성공학 (파생변수)

| 파생변수 | 계산식 | 도메인 근거 |
|---|---|---|
| 산-광석비 (`acid_to_ore_ratio`) | `황산투입량_L / 원료투입량_kg` | 침출 공정 핵심 화학양론 지표. 산이 부족하면 미반응 금속 잔류, 과다하면 불순물까지 같이 녹아 선택도 저하 |
| 침출강도 (`leach_intensity`) | `침출온도_C × 침출시간_hr` | 반응속도론(Arrhenius)적으로 온도·시간이 결합해 반응 진행도를 결정. 개별 변수보다 결합 변수가 회수율과의 관계를 더 잘 설명할 가능성 |
| 총불순물 (`total_impurity_pct`) | `Cu_불순물_pct + Fe_불순물_pct + Al_불순물_pct` | 불순물이 목표금속과 경쟁 반응(공침·착물형성)을 일으켜 회수율 저하 요인으로 작용 |
| 목표금속 순도비 (`target_purity_ratio`) | `(Ni_함량_pct + Co_함량_pct) / (Ni_함량_pct + Co_함량_pct + total_impurity_pct)` | 원료 내 회수 대상 금속 대비 방해 성분의 상대적 비중 |
| 분석월 (`analysis_month`) | `분석일자`에서 월 추출 | 계절적 원료 수급/설비 드리프트 가능성 탐색용. §6.2 검증에서 상관 미미 시 최종 피처에서 제외 |

### 6.1 성능 기여 검증 (ablation test)

`validation.py`에 다음 절차를 구현한다:

1. Case A: 원본 변수(조성 8종 + 공정조건 4종 + 원료등급)만 사용한 모델
2. Case B: Case A + 파생변수 5종 추가
3. 동일한 K-fold 교차검증으로 Ni_회수율_pct, Co_회수율_pct 각각에 대해 R²/RMSE 비교
4. Case B가 유의미하게 개선되지 않는 파생변수는 최종 피처셋에서 제외하고, 그 판단 근거를 노트북에 기록

### 6.2 원료등급 채택 여부 검증

동일한 ablation 방식으로 "조성 변수만" vs "조성 변수 + 원료등급 원-핫 인코딩"을 비교해 최종 포함 여부를 결정한다.

## 7. 데이터 검증 (정합성 + 시각화)

`validate(df)`가 수행하는 작업:

- **정합성 체크**: 정제 후 모든 수치 컬럼이 데이터사전의 정상 범위 내에 있는지 자동 assert, 위반 시 경고 로그 출력
- **결측치 처리 전/후 비교**: 컬럼별 결측 비율 막대그래프 (처리 전 vs 후)
- **분포 확인**: 이상치 제거 전/후 히스토그램·박스플롯 (특히 Ni_함량_pct, 황산투입량_L, 침출온도_C)
- **상관관계 히트맵**: 원본 변수 + 파생변수 vs Ni/Co_회수율_pct
- **클래스 분포 확인**: `원료등급`(A/B/C) 및 `is_duplicate_batch` 플래그의 값별 빈도 확인 → 불균형이 심하면 §9 불균형 대응 방침에 따름
- 모든 플롯은 `reports/figures/`에 PNG로 저장, 노트북에도 인라인 표시
